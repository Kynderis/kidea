# Reviewed work replanning and rounds — R09 B1

Public action: `resume`. Operations: REPLAN_WORK, CREATE_ROUND, SWITCH_ROUND, RETURN_ROUND. These change metadata only; no product/Git/build/deployment operation is run. Use one cooperative writer and the existing local-folder policy.

First create a product-owned JSON proposal file under the authorized authoring scope. Its immutable reviewed bytes specify one operation, reason and nextAction. Read it through resume READ `requiredFiles`, together with every new scope/input/completion/baseline reference. Use approve to bind a package to the exact proposal and affected sources, owned by the current item (and other affected owners as needed). An approved unrelated package cannot authorize a cycle operation.

The mutation request contains operation, permission, expectedBasis, expectedProjectId, expectedOwnerId, expectedGit, requiredFiles, proposalRef (whole file), reviewId, conditionsMet:true, statement. Permission has root, readProject:true, allowReadLocalGit, allowWorkCycle:true, ownerId, statement and confirmed localFilesystem/noActiveSync/singleKideaRun assumptions. A stored proposal cannot grant those rights or authenticate Human approval.

| Operation | Proposal fields beyond operation/reason/nextAction | Contract |
|---|---|---|
| REPLAN_WORK | items, dispositions, nextItemId | Replace the main work items of the current round, preserving other rounds. Each item supplies structural Item fields only: omit gateIds/resultRefs/executionStatus; the helper derives them. Every prior item has `{id,decision:PRESERVE or REASSESS or RETIRE,reason}`. PRESERVE requires unchanged structure and retains progress. REASSESS retains result history but reopens leaf TODO; groups derive completion. RETIRE cannot remove STEP, current owner or retained return point. All affected dependency consumers and ancestors require reassessment, including no-diff downstream steps. |
| CREATE_ROUND | round, baselineRef, items | Add a CHANGE/BUGFIX round with exactly ten fresh STEP/GROUP UNEXPANDED definitions and sequential dependencies; current work stays selected. baselineRef and round scope must be reviewed. BUGFIX requires a pinned releaseRef; no fabricated running baseline. |
| SWITCH_ROUND | targetRoundId, nextItemId | Explicitly enter the first incomplete STEP of another round, preserving current item/nextAction on a ROUND_RETURN frame. Never copy completion/approval into the new round. No implicit Git branch switch. |
| RETURN_ROUND | none | Return to the exact saved original item only after all current-round STEPs are complete and relevant/global blockers are resolved. Preserve the original unfinished work. |

For item definitions supply id, roundId, name, kind, parentId, shape, decomposition, scopeRef, inputRefs, completionRef and dependencyIds. New/reassessed references must be covered by the selected review. Unaffected items preserve existing approval/progress; affected old reviews are detached from live work, their files and exact checkpoint snapshots retained. The selected current plan review is retained when owners remain valid; it does not replace final-output acceptance. Revalidate/revise stale source reviews through approve before a dependent mutation; never declare meaning unchanged solely to unblock a write.

Replanning can select step1 while preserving an IN_PROGRESS leaf on a WORK_RETURN frame. Explicit SELECT of that item consumes its matching top WORK_RETURN frame. These frames are continuation metadata, not permission. Active unresolved impact still requires change ASSESS/review/CLOSE. If metadata references prevent retirement, resolve those references in a reviewed scope rather than deleting them blindly.

Status/schema validate identity, parent/dependency constraints, cycles, review ownership and pinned release records. The helper additionally checks the reviewed proposal, dispositions and input basis. It cannot prove that the Human comparison or claimed baseline is semantically correct; the caller must inspect actual sources and running-state evidence. Checkpoint preimages, retired reviews and per-operation request/input snapshots remain available. Missing permission, pending writes, source/Git changes or invalid projections reject writes; no silent schema migration or automatic replay.
