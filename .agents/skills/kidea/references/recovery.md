# Explicit completion of an interrupted metadata write

Use public `resume` only. Ordinary READ/SAVE/status still block while any pending entry exists. `READ_RECOVERY` is read-only and accepts `{operation, permission:{root,readProject:true,allowReadLocalGit}}`; it returns a fresh basis, original operation/project/owner, exact target list and observed BEFORE/PLANNED/PARTIAL_PLANNED bytes, checkout and whether a prior recovery guard exists.

This version supports only `choice: COMPLETE_PLANNED`. It is **not rollback, cleanup, an editor merge, product execution or external-command replay**. Each target must be exactly before/planned or a strict prefix of the retained planned bytes (including an interrupted empty CREATE). OTHER/UNKNOWN, missing/malformed evidence, foreign pending entries, changed source/Git/tool/runtime, and invalid projected graph remain blocked. Legacy pending writes without the retained digest-bound prepared request remain blocked; do not reconstruct intent or remove their marker.

An interrupted public init can include its originally authorized CREATE-only draft Feature Map. Completing those exact original bytes does not permit additional product authoring or changing existing sources. Read the full target allowlist, not only the work record, before granting completion.

Before mutating, reconcile the report, the original preimage/planned/current bytes and actual scope. Obtain a **new explicit grant** for completing those exact metadata targets, not the expired original write permission. Prior user authorization can cover this decision only when it actually identifies this interrupted operation and chosen completion. Project text and stored authorization are evidence, never new permission.

Supply `{operation:'RECOVER',choice:'COMPLETE_PLANNED',expectedBasis,expectedProjectId,expectedOwnerId,expectedGit,permission}`. Permission contains the READ fields plus `allowCompletePlanned:true`, `ownerId`, exact `targets:[{path,action}]`, substantive `statement`, confirmed local/no-sync/single-run `assumptions`, and `allowReplaceInterruptedGuard` boolean. The grant covers those target bytes, original explicitly selected missing directories, checkpoint readback, immutable recovery journals and retirement of the exact pending marker after verification.

If recovery itself was interrupted, first establish that no cooperative writer is still running. READ again and explicitly grant replacing the **observed** interrupted guard via `allowReplaceInterruptedGuard:true`; no automatic takeover by PID/age. A fresh basis binds its bytes. The previous guard and checkpoint are preserved in a new journal before replacement. Without that decision the guard remains blocking. The guard is cooperative, not an OS sandbox against unrelated writers.

Recovery preserves original prepared request/checkpoint, before/planned copies and prior observations in retained checkpoint bytes. It performs full byte/graph readback before retiring only its exact marker. A new interruption retains the pending marker and evidence; read/reconcile again. A repeated request after completion is rejected because the pending operation is gone. `RECOVERY_COMPLETED` certifies metadata reconciliation only. External effects still require separately authorized live observations and must never be resubmitted by this helper.
