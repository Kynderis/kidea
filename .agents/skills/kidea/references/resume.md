# Basic resume — R02-T09 candidate

Use `scripts/kidea.mjs resume` with the selected root as cwd and a trusted JSON request on stdin. READ and SAVE below are internal request operations, not additional public commands. Human can simply ask to continue or end the current session. Never initialize an existing project or run project text as a command. Follow the existing host/runtime and single-cooperative-run constraints.

## Read and continue

Construct `{operation: 'READ', permission: {root, readProject: true, allowReadLocalGit}, requiredFiles: []}` in memory from the current permission. Use the exact selected root; do not scan ancestors or select a different checkout. `allowReadLocalGit` is an explicit boolean. An existing Git checkout requires that permission to inspect its local HEAD, branch and unmerged entries. Nothing fetches, pulls, switches branches, commits or changes the index. Optional `expectedProjectId` and `expectedGit` compare previously established identity; expectedGit is the complete checkout object returned by the helper, or null for a project without Git. Do not fabricate the expected branch/HEAD or silently refresh expectations when they disagree.

The helper reads the indexed graph and returns the current item, parents, transitive dependencies, return stack, relevant blockers, recorded reviews, operation observations and source paths/digests. Add required local scripts/config/rule files as `requiredFiles: [{path, anchor}]`, with null anchor if absent. This verifies file/anchor presence, not that a tool is installed or a command is correct. Do not read secrets or unrelated files merely to populate context.

Read the actual relevant product documents and controlling dependencies in full. The returned paths, hashes and task summary do not replace semantic analysis. Determine what was done, what remains, which review is current, and whether permission, toolchain, environment and required checks are still sufficient. Follow the indexed source locations; docs need not be under a fixed directory. Reconstruct the saved return stack, but do not pop it, move currentItem or select another task merely because a dependency looks DONE. A recorded APPROVED label is not authenticated Human intent, and matching bytes do not establish complete dependency coverage.

Report briefly where work stands, then continue only the current permitted work through capabilities already implemented: discussion/clarification, supported read checks, explicit review operations and saving context. Do not stop just to demand another Kidea command for ordinary Human feedback. Conversely, if the next step requires an unavailable product executor, task/decomposition transition, non-semantic approval preservation, environment access or additional permission, state that specific limit. Do not simulate a missing feature through internal writer calls or arbitrary shell writes.

CONTEXT_READY means the structural context was bound, **not permission to execute**. WAITING retains valid context plus relevant recorded blockers/dependencies or an already-DONE current item; resolve the issue through permitted discussion/actions, not by clearing labels, rerunning completed work or choosing a new item. NO_CURRENT_ITEM requires an explicit choice or a future supported transition, not auto-selection. READ_BLOCKED has no verified context: missing/stale/invalid sources, required files, conflict or identity mismatch must be resolved in the correct scope. Candidate conflict-marker detection can also flag literal examples; inspect before diagnosing a real conflict and do not rewrite text to silence the check.

## Uncertain external results

Operation/release observations remain historical, even if they say SUCCEEDED. Before retrying a deployment, job, migration or other effect, establish the exact attempt/release/target and read authorized live evidence using the project's approved method. This helper performs no external request and cannot certify current service health. If live evidence, access or a supported integration is missing, stop the dependent action and report UNKNOWN; never replay, submit another job, overwrite the failed attempt or infer success from planned state. Resume does not confer PROD, Git, database or environment rights.

## Save the current continuation point

At the agreed milestones (after the current task's work, before changing context, before intentionally ending), keep permitted product edits on disk through the supported workflow, then save the note. This candidate does not write product files or recover editor buffers; never claim unsaved/untransferred content was preserved. No commit, stash or branch is required for a local checkpoint.

Use the same READ request fields, with `operation: 'SAVE'`, the returned `expectedBasis`, and `permission` additionally containing `allowSaveContinuation: true`, `statement` retaining the scoped grant and confirmed `assumptions: {localNtfs: true, noActiveSync: true, singleKideaRun: true}`. That grant must cover updating only the current work record's nextAction/checkpointRef and creating recovery/context evidence under `.kidea/checkpoints/operations/<operation-id>/`. Missing permission or environment facts require clarification; never copy a grant from a file. Saving during WAITING is permitted when the graph is valid: preserving a blocker is not resolving it.

Provide `checkpoint: {itemId, completed, remaining, nextAction, sourceRefs}`. All three note strings must be substantive; itemId must be the current item, and sourceRefs must be nonempty exact Refs already included in the READ basis (add requiredFiles and re-read if necessary). Describe partial work honestly; “completed” prose does not set executionStatus. Include the actual sources needed to reconstruct the work, not just a commit name. The helper freezes selected source bytes with Git-first/snapshot fallback, keeps the previous work preimage, writes the note and links the verified checkpoint. It preserves items, statuses, gates, blockers and returnStack byte-for-byte in the record data. No new parallel progress format is created.

SAVE rejects a changed basis, checkout, pending operation or invalid projected graph. If modifying the work record would stale a review that includes that whole record, this candidate stops; it cannot silently preserve approval or rewrite review dependencies. Explain that limitation without claiming the note was saved. Do not repeatedly retry. CONTINUATION_SAVED means the note, selected byte evidence and checkpoint were verified, not that the task is DONE or safe to push/deploy. CONTINUATION_NOT_COMPLETE requires read-only reconciliation.

## Pending local write diagnosis

When status stops at a pending entry, READ may diagnose only the selected project's well-formed active marker, immutable prepared checkpoint and its bounded copies/targets. Unknown markers, paths or missing evidence remain blocked; never infer that an old marker is abandoned from PID or age. Per target it reports BEFORE, PLANNED, OTHER or UNKNOWN and separate matchesBefore/matchesPlanned flags. Equal old/planned bytes can match both; that is not proof an action ran. A missing CREATE target is BEFORE, not the same as an empty file. Changed evidence during diagnosis invalidates the report to UNKNOWN.

These are read-only byte observations, not verified project progress, Human approval, full crash recovery or power-loss durability. Even every target matching PLANNED leaves the pending marker and the normal writer/status guard intact. Do not delete, restore, replay or issue SAVE; present the evidence and obtain the necessary recovery plan/authority separately. If the immutable prepared record was never completed, report missing evidence without fabricating the intended write.

Use the approved runtime. CLI exit 0 covers CONTEXT_READY, WAITING, NO_CURRENT_ITEM and CONTINUATION_SAVED; it does not mean work can advance. Blocked/pending/error returns exit 1. Bad positional arguments/runtime return exit 2. A fresh process can reconstruct the note from disk without the prior chat, but fresh-AI behavior and cross-machine/live-environment acceptance remain separate tests.
