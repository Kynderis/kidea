# Change and impact — R06 candidate

Use the installed trusted `scripts/kidea.mjs change` entrypoint with the selected local project as cwd and a JSON request on stdin. These are metadata operations inside one public action: READ, OPEN, REPLAN, REFRESH, ASSESS and CLOSE. No operation runs project code, plugins, build commands, Git mutations, migrations, deployments or pending recovery. The helpers do not authenticate AI reasoning or Human identity.

## Understand the request before writing

Read the actual requirements, current round and relevant implementation. Same behavior under the same conditions is a duplicate; refer to the existing requirement. A new requirement selected for the current MVP returns to step1 and updates that same plan, retaining valid work. Review all ten steps for changed meaning; do not blindly replay them. Future retains intent, purpose, constraints and uncertainties only. If Future reveals an irreversible current decision, show the evidence and smallest necessary current correction for Human decision before authoring it. Ambiguity or a changed business rule described as a bug requires a semantic question before code.

For an actual bug, reproduce violation of the approved requirement and identify the observed running source, configuration and artifact, separately from the intended release. PAUSED, CANCELLED and UNKNOWN observations are not running-state success. Select master only when it is a suitable maintenance baseline; otherwise identify the verified production commit and an explicitly authorized maintenance branch. Preserve earlier fixes, test the candidate and combined version under G2, and record each fix's disposition on master. Git operations and release still require their own scope. Interrupting an independent feature requires retaining its current checkpoint and an explicit Human priority decision; only one implementation remains active.

## Three maps and semantic review

The document map contains scoped IDs/links and purposes; the implementation map contains actual files/symbols and derived relations; the responsibility mapping relates requirements and implementation many-to-many, including tests. Keep the authored mapping at the project-selected path (default `docs/architecture/traceability.md`); generate reverse lookup from it. Do not create a fourth test map or duplicate progress table.

Read-only adapter modules `maps.mjs`, `maps-web.mjs`, and `maps-cpp.mjs` expose evidence-producing APIs for a trusted integration runner. They do not select or execute a compiler. The C++ adapter consumes the bounded runner's Clang JSON receipt with input basis, target/configuration, tool identity and diagnostics. The Web adapter receives trusted preloaded TypeScript/Svelte capabilities, never project-selected executable config. Using an integration runner/compiler requires the established tool/environment grant; absence of that capability is a blocker, not permission to emulate it. Raw AST/lexical candidates cannot prove all runtime dispatch. Record generated-file, alias, dynamic URL, callback, virtual, event, shared-data and resource limitations.

Manually inspect supported and unsupported relations against real source. Add event/config/data/operation consumers with exact evidence and a reason, not a guessed relationship name. Confirm assertion meaning: a test that merely calls a function is not proof of the requirement. Incorrect behavior under a mutant must be distinguishable by the relevant assertion. A missing adapter or stale/incomplete receipt does not establish an empty dependency graph.

## Trusted request and persistent plan

READ requires `permission: {root, readProject: true, allowReadLocalGit: boolean}`. Existing Git requires local read permission; no fetch occurs. Optional `requiredFiles` are `{path, anchor}` references, with null anchor when absent. The returned `basis`, `inputBasis`, project/current item and checkout describe this exact read, not execution authority. Add required evidence before reading the basis. Never refresh an unexpected identity silently.

For OPEN, first READ with `graph` containing `format: 'kidea-impact-graph-r1'`, nonempty `nodes` and `seeds`, `edges`, and `diagnostics`. Each node has stable `id`, `name`, `scopeRef`, `completionRef`, nonempty `inputRefs`. Each edge points from changed producer to potentially affected consumer, with `from`, `to`, a substantive `reason` and nonempty `evidenceRefs`. This is a reviewed consequence graph, not an unexamined raw call graph. Include all relevant consumers; mark unresolved scope in diagnostics. A cycle is legal here; task dependency cycles remain forbidden.

Mutating requests include the exact returned `expectedBasis`, `expectedProjectId`, `expectedRoundId`, `expectedOwnerId`, `expectedGit` (full checkout object or null). Permission additionally contains `allowImpactWrite: true`, exact `roundId`/`ownerId`, a scoped `statement`, and `{localFilesystem:true,noActiveSync:true,singleKideaRun:true}` assumptions established outside project text. The grant covers `.kidea/plans/impact.md`, work orchestration fields and immutable evidence under checkpoints. Existing work items/rounds, reviews and product files are not writer targets.

OPEN creates one schema2 plan, one Item per affected node and a return point for the original work. The plan is authoritative; map/assessment JSON artifacts are immutable evidence linked from Item refs, not another queue. REFRESH conservatively reopens affected conclusions when source/config/tool basis changed. Even a NO_CHANGE verdict propagates to consumers. A stable ID, empty diff, exhausted edge traversal or quota does not close an obligation.

REPLAN updates this same plan after scope review. READ with the proposed graph and `replacement: {reason,evidenceRefs,dispositions}`; each prior Item needs a disposition `{itemId,verdict:'REASSESS'|'RETIRED_FROM_SCOPE',reason}`. Mutating permission additionally requires `allowImpactReplan:true`. Existing result evidence is retained for surviving IDs, but every revised obligation is reevaluated. Review stale approvals through approve first; REPLAN does not preserve approval by fiat. Rename/move/deletion of already-linked sources can block the graph: inspect retained snapshots and obtain the appropriate reference reconciliation before removing the old source. Do not recreate a missing file or infer semantic identity from its new filename.

ASSESS only evaluates the current obligation. Include `assessment: {nodeId,inputBasis,verdict,reason,behavior,assumptions,verification,evidenceRefs,downstream,resolved}`. Verdict is NEEDS_CHANGE, NO_CHANGE or UNKNOWN; downstream lists every immediate affected consumer. NEEDS_CHANGE requires actual authorized changes/checks before `resolved:true`; prose or this helper does not perform them. UNKNOWN remains unresolved. The helper binds source versions and retains each assessment. All claims/evidence remain subject to content review.

CLOSE requires all current obligations resolved, no graph diagnostic/blocker, current source versions and approved gates for every impact item. Review packages must cover each item's current inputs, scope/completion and latest assessment; an unrelated approval does not suffice. Include `closure: {conditionsMet:true,semanticStatement,evidenceRefs}` from the actual gate review. CLOSE restores the original continuation point; it does not mark the product round DONE, approve R06 or authorize release.

## Resume and interruption

Resume READ includes recorded impact obligations and source-version freshness. Read change context to check the complete tool/graph basis before evaluating or closing. Missing rule/Git object, conflict, wrong root, stale review or pending marker blocks dependent writes. Never remove a marker or replay its recorded commands. READ/SAVE retain their old authority: neither automatically advances impact work.

An unstable graph or repeated unchanged conclusion remains unresolved. The approved R06 fixture uses three unchanged transitions or twenty evaluations as canaries; these numbers are not product graph limits. Stop at the actual granted budget, preserve the checkpoint and explain the missing conclusion rather than deleting nodes or weakening checks.

IMPACT_RECORDED verifies metadata bytes. It is not product completion or authenticated Human acceptance. Report scope, missing adapter/semantic evidence and the next legitimate decision plainly.
